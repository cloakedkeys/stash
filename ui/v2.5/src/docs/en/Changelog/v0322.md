### ⚠️ Notable Changes

* This version updates the database: stories, per-user favourites, an organised flag on groups, more than one image per performer, and scenes that share a file. Make a backup first. Stash can't go back to an older version once it has run.
* PostgreSQL 18 is now the version Stash is tested with. The Docker Compose example on the PostgreSQL page of the manual uses it, and keeps its data under `/var/lib/postgresql` instead of `/var/lib/postgresql/data`. Moving an existing PostgreSQL 17 database to the 18 image needs `pg_upgrade`; the manual has the steps.
* PostgreSQL no longer needs the `plperl` extension, and runs with an ordinary account. Regex filters now give the same results as on SQLite. Plugins that call `regex_match` through raw SQL need to use PostgreSQL's regular expression syntax. A backup made before this version can only be restored on a server that has `plperl`.
* Stash won't start on a PostgreSQL database that isn't UTF8.
* Requests that list every saved filter, scraper type or scrape result can now include stories: `STORIES` in `FilterMode`, `STORY` in `ScrapeContentType` and `ScrapedStory` in `ScrapedContent`. Clients built to accept only a fixed list of values may need updating once stories are in use.
* `_` and `%` in text filters and the search box now match only themselves, not any character. Use "matches regex" for patterns. Upgrading rewrites saved filters and default filters that relied on them as wildcards into "matches regex" filters that find the same things, and so does importing an older export. This includes custom field filters. The few that can't keep their meaning, such as "excludes" on aliases or URLs, and search box text, are left as they were and named in the log. The config file is backed up before its default filters are rewritten.
* On PostgreSQL, custom field values now read as the same text as on SQLite, so "includes", "excludes" and regex filters find the same things on both. True and false read as `1` and `0`, so "includes true" no longer matches; whole decimals read as `5.0`, so `^5$` no longer matches; and very large or very small decimals read as `1.0e+20` or `1.0e-05`. Saved filters that relied on PostgreSQL's old text may need changing.
* PostgreSQL users upgrading straight from v0.32.0: v0.32.0 matched custom field "equals" filters ignoring case and treated `_` and `%` as wildcards. Since v0.32.1 they match exactly, so check saved custom field "equals" filters. For example, "equals `Site_A`" no longer finds `site-a`.
* Maximum session age, in Settings > Security, is now chosen from a list, up to 400 days, the most browsers allow. A longer saved value counts as 400 days.
* Options changed inside the image viewer used to be saved only in that browser and override Settings > Interface. They now share one saved value, so options saved in a browser before go back to what Settings says.
* Other websites can no longer read or change your library through your browser, log you out, or run scrapers. A plugin, userscript or page on another site that calls Stash from the browser without an API key now gets refused. Add it to the new `trusted_origins` list in `config.yml`, or give it an API key. The manual explains how. Logging out now needs a POST, so a bookmark or script that opens `/logout` stops working.
* New generated files are kept together, two folders deep by the file's hash, under `generated/video` and `generated/image`. Large libraries no longer have tens of thousands of files in one folder. Files already generated keep working where they are. Settings > Tasks > Migrations > Move generated files to the current layout moves them into the new folders.
* The bundled SQLite is now 3.53.4. Out-of-date database statistics no longer make the Studios page slow. Nothing needs to be done when upgrading.
* Lists now offer 20, 40, 60 or 120 items per page, and a custom size of up to 255. A web address or saved filter asking for more shows 255.
* Settings > Library > Media Content Extensions now refuses an extension Stash can't read, such as `exe`. Settings already saved are left alone.
* On Windows, FFmpeg downloaded by Stash now includes the fast AV1 decoder. The download is bigger, 186 MB. An FFmpeg you already have is kept until you download it again.
* With several accounts, JavaScript plugins now act as the person who started them, with that account's roles and library limit. Before, a plugin started by an editor, or a hook set off by a viewer, could do admin-only things. A hook that does admin-only work now fails when a non-admin sets it off. Python plugins already worked this way.
* Generate now does every item in its list that exists, and logs the ids it skipped, instead of doing nothing for the whole list. A real database error stops the job.
* On PostgreSQL, items that a sort ranks the same now come back in the same order as on SQLite, and with no sort lists come back in id order.
* Stopping Stash while it builds or upgrades its database now waits for that to finish, so the database is never left half done. The log says how to stop at once anyway. A very long upgrade can only be stopped by ending the process, so for large upgrades raise Docker's `stop_grace_period` or systemd's `TimeoutStopSec`.

### ✨ New Features

* **Stories:** stories have their own pages and a reader that shows older text encodings correctly.
  * Scans pick up stories from text files.
  * A story's details can be scraped from its web address, with a built-in Literotica scraper.
  * Import Story adds a story to Stories from its web address, and saves a scraped story's text as a file in a chosen folder.
  * A story's text file can be moved onto another story, and removing a story can delete its file too.
  * Stories are included in exports and imports, and the API has story permissions.
* **Scenes that share a file:** several scenes can share one file, each with its own start and end time, set on the scene's Edit tab or from File Info > Create scene from part of this file. For now, a part still plays its whole file, and its previews and sprites cover the whole file.
* **Split scene:** an option to copy the original scene's markers.
* **Favourites:** scenes, images, galleries, groups and audio can be favourited. Favourites are kept per user.
* **Organised:** groups can be marked organised. Images, galleries and studios can be sorted by organised; performers, studios and tags by favourite.
* **Performer images:** a performer can have more than one image, managed on the performer page.
  * Hovering over a performer card shows their second image.
  * A setting shows a random image on performer cards.
  * A performer's picture can be set from a scene cover or the current video frame.
  * Scraped images you didn't pick are kept as other images.
* **Duplicate images:** Settings > Tools has a duplicate image finder, like the one for scenes.
* **Image hashes:** animated GIFs, animated WebP images and video clips now get a perceptual hash.
* **Gallery reader:** a continuous reader that scrolls through a gallery, with previews for video clips.
* **Image viewer:** an option to stop the mouse wheel changing images.
* **Scene player:** subtitles embedded in a video are shown.
* **New scene page:** videos can be uploaded from it.
* **Tags:** a sort by scene count including sub-tags.
* **Copy to PostgreSQL:** a SQLite library can be copied into a PostgreSQL database with `--migrate-sqlite-to-postgres`. The PostgreSQL page of the manual has the steps, and how to upgrade PostgreSQL with `pg_upgrade`.
* **Settings:** a close button returns to where you were. Web addresses in descriptions are links. Downloaded FFmpeg can be removed.
* **Scrapers and stash-box:** requests send a browser User-Agent by default.
* **Desktop notifications:** they say when a task failed or was stopped.
* **Countries:** country names come from Unicode CLDR and are labelled Country/Region. Custom localisation can change them.
* **Scans:** Synology `@eaDir` folders are skipped.
* **Docker:** Python packages are kept across updates.
* **Scene lists and the queue** load smaller covers, so they open faster.
* **Interface:** the Stash button shows a home icon, the favourite heart sits at the bottom-left of card pictures, scraper sites are shown as full addresses, and going to Tasks shows the task queue.
* **Phones:** the settings page, Help, the menu, pop-ups, lists and toolbars fit the screen. The page reaches the screen edges on phones with a notch.

### 🐛 Bug fixes

* **Generated files**
  * Videos whose pixels aren't square, such as DVD rips, got stretched covers, previews, sprites and marker images. Files already generated stay stretched until they're generated again with overwrite on.
  * Scene previews made with ffmpeg 9 played choppily in Firefox.
  * A preview stopped being built when some of its segments came out empty.
  * Portrait sprites could come out larger than the set size.
  * Image thumbnails lost their transparency, including AVIF ones.
  * When a file changed, its old thumbnail and clip preview weren't removed. When two copies of a video were in different scenes, changing one removed the other scene's preview and sprite.
  * Merging scenes left their markers' video previews behind, and a deleted scene's marker preview folder stayed.
  * The downloaded FFmpeg zip stayed in the config folder after it was unpacked.
* **Scanning and files**
  * A replaced file wasn't noticed when only its size changed.
  * A renamed path wasn't recognised when only an accented letter changed case.
  * Files that are no longer videos or images kept their scene or image after cleaning.
  * A GIF inside a zip was stored differently from one outside it, and the WebP animation flag was read from the wrong byte.
  * Text files that aren't SVG images were accepted as images.
  * When the same picture was in two galleries, one gallery's pages could come out in the wrong order or get the wrong cover.
  * Deleting a file could overwrite another one. A file with a very long name failed to delete without saying why.
  * Deleting the last image in a zip gallery left the zip behind.
  * A zip stayed open when a file inside it couldn't be opened.
  * Zip galleries were lost when a library moved between Windows and Linux, and weren't recognised when importing.
  * Delete protection didn't work for library folders saved with a trailing slash.
  * Stories were lost when a library folder was spelled differently.
  * Video fingerprints known to be junk were saved.
* **Scrapers, stash-box and identify**
  * Studios from scrapers failed or lost their image.
  * Stash-box batch tagging failed for every item when one of them had been deleted. A deleted item is now skipped.
  * Identify, auto tag and stash-box batch tagging did the work twice for an item listed twice.
  * Searching stash-box for several performers at once found nothing.
  * Identify, the tagger and scene scrapes crashed when a stash-box sent back the wrong number of results. The tagger could also show a scene another scene's match.
  * Identify failed on performers and studios that already existed.
  * Tagging from StashDB or identifying replaced a performer's other images.
  * A new performer, group or studio filled in by a scrape couldn't be saved.
  * Scraped aliases containing a comma were split, attributes could land on the wrong performer, and XPath scrapers lost line breaks in Details.
  * "Now" wasn't accepted as the end of a career.
  * Failed scraper scripts left zombie processes behind.
  * A scrape from URL that found nothing, a script scraper that returned no images, and a scraper that couldn't build its query URL didn't say so.
  * The scraper site list crashed the settings page.
* **Lists and filters**
  * Filters treated `_` and `%` as wildcards in "equals", "includes", "excludes" and the search box.
  * A filter that a list doesn't support crashed the page, and filter badges showed old names.
  * With sub-tag content shown, the tag list counted only a tag's own scenes.
  * Excluding a tag from the scene list was slow.
  * On SQLite, random sort and shuffle gave items in id order whatever the seed. They now give the same orders as upstream Stash.
  * On SQLite, a custom field "matches regex" filter failed when a field held a number.
  * A custom field regex filter failed when its pattern was a number, such as `5`.
  * A custom field "not between" filter with fewer than two values crashed the request. On PostgreSQL, "equals" and "not equals" with no value failed instead of matching nothing and everything, as on SQLite.
  * The list of all saved filters had no set order on PostgreSQL, and on SQLite once its statistics were refreshed. Both now sort by type, then name.
  * The Studios page was slow on large libraries, and stayed slow until the database statistics were refreshed.
  * A studio's Performers tab counted other studios' media, and left out O-count and play stats.
  * A performer's play count missed some plays, and tapping the play count button counted a play.
  * Open scene lists were fetched again on every playback save.
  * The tagger page jumped when a scene above disappeared.
* **Players and viewers**
  * Filters, rotation and the A-B loop carried over to the next scene. Captions stayed off when returning to a scene.
  * The image viewer jumped to another image when the list changed. Dragging in it changed images or closed it. Closing it warned about unsaved changes.
  * Keyboard shortcuts didn't work on pages that also show a list.
* **Editing**
  * Leaving a new, unsaved item, or going to another group, studio or tag, didn't warn about unsaved edits.
  * An edit using a tag that doesn't exist didn't say "tag not found".
  * Rating, favouriting, adding an O or a play, saving activity or bulk editing something that doesn't exist showed a database error instead of "not found". So did markers, gallery chapters, sub-groups, performer images, file assignment and merges that named a missing item, and edits linking to a studio, group, tag or file that doesn't exist.
  * Listing the same group twice on a scene or audio track, or adding a containing or sub-group that's already linked, showed a database error instead of saying so.
  * An edit listing the same item twice, such as an image's gallery, failed with "not found".
  * Numbers written with an exponent, such as `1e20`, were saved as `0` in custom fields, interface settings and plugin settings. A number too big to store, such as `1e400`, is now refused, and so is a saved filter holding one, which used to lose the value.
  * Numbers inside lists in interface and plugin settings came back as text after a restart, so a default filter on a number custom field stopped matching.
  * Right-clicking after tags or performers didn't offer Paste.
  * A failed save carried on as if it had worked.
* **Tasks**
  * Task notifications stopped after a queued task was cancelled.
  * Requests made while a full import reset the database failed instead of waiting.
  * A full export on PostgreSQL crashed the server.
  * Exporting or generating with an item listed twice exported nothing, generated nothing, or stopped the job. Each item is now handled once.
* **PostgreSQL**
  * Long story and audio titles couldn't be saved.
  * Paging through a list could show an item twice or skip one.
  * Group edits made at the same moment could fail, or leave two groups inside each other.
* **Setup and configuration**
  * The library folder set by `STASH_STASH` wasn't used, or shown in the setup wizard.
  * An empty `STASH_` setting was treated as set.
  * Creating a new database, resetting it or restoring an old backup renamed UI and plugin settings in `config.yml`, such as `object_filter` in default filters. Only config files from before v0.26 are converted now.
  * Upgrading from v0.25 or older lost the settings of plugins with an underscore in their name, such as `my_plugin`.
  * On SQLite, starting or stopping Stash, or resetting its database, while another program was writing to the database paused about 5 seconds.
  * On Windows and macOS, stopping Stash just after it started could leave it running until it was killed.
  * When a database upgrade failed to start, the SQLite file stayed open until Stash exited.
  * Stopping Stash before a database upgrade, or after a while of only reading, left SQLite's `-wal` and `-shm` files behind.
  * When a database upgrade failed, the automatic restore from the backup failed on Windows, and anywhere when the backup folder was on another drive, leaving the database half upgraded.
  * Stopping Stash while it was creating a new database, during an upgrade started from the web page, or while copying to PostgreSQL, left the database half built.
  * Plugins got no session cookie, so on a server with a password their calls back to Stash were refused, and JavaScript plugins couldn't use per-user features such as interface settings, favourites and O counts.
  * On Windows, the Microsoft Store stub was found ahead of real Python.
  * When no hardware encoder worked, the log didn't say why.
  * A broken custom ffprobe path was accepted, because Stash checked the ffmpeg file instead, and scans failed later. It's now refused like a broken ffmpeg path.
* **Interface**
  * Links starting with `javascript:` could run.
  * A very large maximum session age broke the settings page.
  * Audio disappeared from the menu when a menu item was turned on or off.
  * Hover pop-ups could open outside the window, and card count pop-ups couldn't be opened on touch screens.
  * Button hints stayed on screen on touch screens. Only error messages now open in the box titled Error.
  * Tapping an image card's picture didn't open the full-screen viewer.
